## 1. 目的・背景

新人CAが求職者と面談する際、求職者の業務内容や業界用語が分からない場面がある。
面談を止めずに、その場で「分からない部分」を瞬時に要約・解説する仕組みを提供する。

- 主目的: 面談中のリアルタイム支援（新人CAの理解補助）
- 副目的: 面談ログ・解説履歴を蓄積し、面談後の振り返り・新人研修の教材として活用する

## 2. 利用者・利用シーン

- 利用者: ビズスタジオのCA（当面は新人CAが中心。権限制限は設けず全CAが利用可）
- シーン: 面談中。PCのマイクが「CA自身の声」と「スピーカーから出る求職者の声」の両方を拾う
  - 電話面談: スピーカー通話のためそのまま拾える（主対象）
  - オンライン面談: スピーカー出力で使う（決定）。環境的に難しい場合のみNotta併用
- 使用ブラウザ: Chrome限定（ブラウザ内蔵の音声認識機能を使うため。この機能はマイク入力しか文字化できない）

## 3. 全体の仕組み（概要）

```
面談履歴入力画面
   └─「面談サポート」ボタン（別タブで開く）
         └─ 面談支援画面（新規ページ）
              ├─ マイク音声をChrome内蔵機能で文字起こし → 中央ログに流す
              ├─ 「直近30秒を解説」ボタン → 直近ログをAIに送信 → 右側に解説カード
              ├─ 文字選択時のみ「選択部分を解説」ボタン → 選択文をAIに送信
              └─ 面談終了 → ログ＋解説履歴を面談レコードに紐づけて保存
```

## 4. 画面要件

### 4-1. 入口（既存画面への追加）【確定】

- 設置場所: 面談履歴入力画面の操作ボタン列（削除／一覧に戻る／キャンセル／PDF表示／保存が並ぶ列）の「PDF表示」と「保存」の間
- 仕様: 「PDF表示」と同じ幅のボタン。ラベルは「面談サポート」
- 押すと面談支援画面（Notta風UI）が**別タブ**で開く（面談履歴入力画面を保ったまま併用するため）。求職者名・面談情報を引き継いだ状態で表示し、画面内の「開始」ボタンを押して初めて音声認識がスタートする（開いた瞬間には拾わない）
- 前提: 面談レコードが必ず存在する状態で使う。レコードがない場合は機能しない仕様でよい（仮セッション等は作らない）
- 既存の面談履歴のロジック・データには一切手を入れない（ボタン追加のみ）

### 4-2. 面談支援画面（新規ページ）

3カラム相当のレイアウト（Notta風）:

| 位置 | 内容 |
|---|---|
| 上部 | 求職者名・面談情報、録音開始/停止ボタン、状態表示（認識中/停止中）、使用中の文字起こしエンジン名（「Deepgram」/「ブラウザ内蔵」を小さく表示。v6） |
| 中央 | 文字起こしログ。時刻つきで下に流れ、自動スクロール。手でスクロールを上げたら自動スクロールは一時停止（追従再開ボタンあり）。未確定（発話中）のテキストは最下部に薄色で都度差し替え表示 |
| ログ直下 | 「直近30秒を解説」ボタン（常時表示・大きめ）。文字を選択した時だけ「選択部分を解説」ボタンが出現 |
| 右側 | 解説カードが新しい順に上から積まれる。各カードに「元になった発言の抜粋」と「解説文」を表示 |

- 面談中に片手・一目で操作できることを最優先とする（ボタンは大きく、確認ダイアログは出さない）
- **カラム比率（v6）**: 解説カードが主役。横幅はおおよそ ログ 40% : カード 60%。カード本文は一段大きいフォント＋広めの行間で、面談中に一目で読めるサイズにする。固定エリア（業務内容・転職理由）は右カラム上部に据え置き、時系列エリアはその下でスクロール

### 4-3. 面談サポートタブ（面談履歴・右カラム）【2026-08-27改訂】

面談履歴入力画面の右カラムタブ（初期条件／希望条件／ランク評価／アクション／添付 の並び）に「面談サポート」タブを追加し、記録の管理をここで完結させる。

- **新規作成ボタン**: 選択中の面談の支援画面を別タブで開く（ヘッダーの「面談サポート」ボタンと同じ動作。ヘッダーボタンは面談中のワンクリック用に併存）
- **セッション一覧（Notta風）**: この求職者に紐づく全セッションを新しい順に一覧表示。各行に「面談回次または開始日時」「長さ（開始〜終了）」「作成CA」「削除ボタン」
- **削除**: 確認ダイアログの上で該当セッションのみ削除（面談レコード・他データには影響しない）
- **閲覧**: 行クリックで文字起こしログと解説履歴を時系列表示（読み取り専用。解説はログと区別できる見た目）
- セッションが1件もない場合は「面談サポートの記録はありません」と表示

## 5. 機能要件

### 5-1. 文字起こし【v6改訂: Deepgram ストリーミングが主、内蔵方式はフォールバック】

- **主エンジン: Deepgram ストリーミング**（`useDeepgramTranscription.ts`）。マイク音声を MediaRecorder（webm/opus）で約250msごとの小チャンクにし、WebSocket（`wss://api.deepgram.com/v1/listen`）へ送る
  - パラメータ: `model=nova-3`・`language=ja`（nova-3 は日本語専用指定に対応）・`interim_results=true`・`endpointing=300`（無音0.3秒で確定。定数）・`punctuate=true`・`smart_format=true`
  - 未確定（interim）テキストは「現在の発話行」としてログ最下部に薄色で都度差し替え表示し、`is_final` で確定ログに時刻つきで追加（内蔵方式と同じ構造）
  - 認証: サーバーの `POST /api/interview-support/stt-token` が Deepgram の `POST /v1/auth/grant` で発行した短時間有効トークン（TTL 60秒）を返し、ブラウザは `access_token` クエリで接続する。永続キー（環境変数 `DEEPGRAM_API_KEY`）はブラウザへ渡さない
  - 接続断・エラー時は短い待機（1秒）を挟んで自動再接続（トークンも取り直す）。ユーザーの「停止」では再接続しない。「停止」で WebSocket（CloseStream 送信）と MediaRecorder・マイクを確実にクローズ
- **フォールバック: Chrome内蔵の音声認識**（Web Speech API・`useSpeechTranscription.ts`）。画面起動時に stt-token API を呼び、`available: false`（`DEEPGRAM_API_KEY` 未設定・発行失敗）なら内蔵方式で従来どおり動く。認識が勝手に止まる癖への自動再開処理も従来どおり
- 話者の区別（誰が話したか）は行わない。CAと求職者の発言が混ざったログでよい
- 確定した文だけをログに追加し、各行に時刻を記録する（「直近30秒」の切り出しに使う）
- ページを誤って閉じた場合に備え、ログはブラウザ側にも逐次退避し、保存漏れを防ぐ

### 5-2. 解説（AI要約）— 速度と分量が本機能の生命線

**モデル・呼び出し方**
- 使用AI: Claude Haiku（最軽量・最速のモデル）。「考えてから答える」モード（拡張思考）は使わない
- 指示文（プロンプト）は短く固定し、プロンプトキャッシュ（同じ指示文を使い回して読み込みを速く安くする仕組み）を使う
- 出力の上限トークン数を仕組み側で固定し、長文化を強制的に防ぐ（分量ルールに合わせ200前後を初期値とし実測で調整）

**トリガー（v5改訂: 自動検知が主、ボタンは即時フォロー用 / v6改訂: イベント駆動化）**

【自動検知】**発話が確定するたび**に、前回チェック以降の新しい確定発話をAIに送り、以下3種のカードを判定する（30秒タイマーは廃止。話してから数秒でカードが出る）。該当がなければ何も出さない（沈黙）。暴走防止として、直前のスキャン完了から最低5秒（定数 `AUTO_SCAN_COOLDOWN_MS`）は次のスキャンを待ち、待ち中に確定した発話は次の1回にまとめて送る。新規発話が20字未満なら呼び出し自体をスキップ（無言・相槌区間はコストゼロ）。

| カード | 挙動 |
|---|---|
| ①用語 | 新人CAが分からない可能性が高い業界用語・職種用語のみ。時系列で積む。解説済みリストを毎回渡し再解説しない。最大2件/回 |
| ②業務内容 | 求職者が自分の業務を説明している場面を検知したら「この人は何をしている人か」を知識ゼロ向けに要約。経歴から見える強み・得意も分かる範囲で1行添える。**会社/職務ごとに1枚の更新型**（話が進むたび同じカードを育てる。乱発しない） |
| ③転職理由 | 転職理由が語られたら要点を整理。**1枚の更新型**（後から語られた理由を統合） |

- 検知対象外（沈黙する）: 希望条件・日程調整・雑談など、業務理解と関係ない話
- カード配置: ②③は右カラム上部に固定表示（更新時に軽くハイライト）、その下に①と手動解説カードが時系列で積まれる
- 【手動】「直近30秒を解説」「選択部分を解説」ボタンは従来どおり即時ストリーミング（今すぐ知りたい時のフォロー）
- いずれも送信は「新規発話＋既存カードの現在文＋固定指示文」のみ。面談開始からの全ログは送らない
- コスト目安: 1面談（40分）10〜20円程度

**分量ルール（トリガー別）**
- 選択部分の解説: 結論1行＋補足最大2行。全体で約80〜120字
- 直近30秒の解説: 要点最大3行
- 1行目は必ず「答えそのもの」から始める。「〇〇とは、」等の前置き形式・まとめ・免責は禁止

**指示文に含めるルール**
- CAと求職者の会話が混在している前提で読む。求職者の仕事内容・用語を中心に解説する
- 業界知識・職種知識がない人向けに説明する
- 誤字・認識ミスは文脈から補って読む
- 分からない・確証がない場合は推測で断定せず、その旨を1語添える

**体感速度の設計**
- ボタン押下の瞬間（0秒）にカード枠＋「解説中…」を即表示する。通信を待ってから描画しない
- AIの文字は生成と同時にカードへ流し込む（ストリーミング表示）
- 性能目標: 押下から文字の表示開始まで約1秒以内、全文表示まで約2秒以内（目標値。実測で確定する）
- 実装後にstaging環境で実測し、指示文・出力上限・30秒幅を調整する工程を必須とする

### 5-3. 保存

- 面談中は1分ごとに自動保存し、面談終了時に最終保存する。以下を保存対象とする:
  - 文字起こしログ全文（時刻つき）
  - 解説履歴（トリガー種別、元テキスト、解説文、時刻）
- 保存先: 新規テーブル。既存の面談レコード（InterviewRecord）に紐づける
  - 支援セッション（どの面談・誰が・いつ）
  - ログ本文
  - 解説履歴
- 既存テーブルの変更は行わない（紐づけは新テーブル側が面談IDを持つ）
- 削除: 面談サポートタブから、確認ダイアログの上でセッション単位の削除ができる（削除対象は当該セッションのみ）

## 6. 非機能要件

- 速度: ボタン押下→即カード枠表示（0秒）→文字表示開始 約1秒以内→全文表示 約2秒以内（目標値、実測で確定）
- コスト: 1回の解説 約0.3円想定。送信範囲を直近に限定することで面談時間に関係なく一定に保つ
- 対応環境: Chrome（PC）のみ。スマホ・他ブラウザは対象外
- デプロイ: 純粋な追加機能（新ページ・新API・新テーブル、既存ロジック変更なし）のため、ポータルの運用ルール上 master直push可の範囲で構成する

## 7. スコープ外（今回はやらない）

- 話者分離（誰の発言かの自動判別)
- 録音音声そのものの保存（保存するのは文字のみ）
- 有料の文字起こしAPI連携（将来の差し替え候補として、文字起こし部分は交換可能な作りにしておく）
- 面談支援画面からの面談記録（所感など）の入力
- スマホ対応

## 8. 前提・リスクと検証項目

| # | 内容 | 対応 |
|---|---|---|
| 1 | スピーカーから出る求職者の声をPCマイクが実用レベルで拾えるか（最大リスク） | 実装前に実機テスト。実際の面談と同じPC・スピーカー音量で通話音声を流し、読める文字になるか確認 |
| 2 | Chrome内蔵認識は句読点がほぼ付かず、固有名詞を誤変換しやすい | 要約はAIが誤字ごと文脈で読むため許容。精度不満なら将来有料APIへ差し替え |
| 3 | オンライン面談では相手の声がマイクに乗らないケースがある（イヤホン/PC内部経由） | スピーカー出力で運用（決定）。環境的に難しい場合のみNotta併用。本命対応は将来拡張（会議音声の直接取得＋有料文字起こしAPI） |
| 4 | 長時間面談でログが肥大化 | 表示は間引きせず全量。保存は自動保存間隔で分割送信 |

## 9. 将来拡張（今回は作らないが、壊さないでおく）

- 文字起こしエンジンの差し替え（Avalon等の有料API）
- オンライン面談の本命対応: 会議画面の音声を直接取り込む方式（Chrome内蔵認識では不可のため、有料文字起こしAPIへの差し替えとセットで実施）
- 蓄積した面談ログ・解説履歴の研修教材化（ポータルのAIアドバイザー長期構想 Phase 2「会話保存」と接続しうる）
- 「はい。」等の音声トリガー化（ボタン操作すら不要にする案）

## 決定事項（すべて確定済み）

- 入口ボタン: 面談履歴入力画面の操作列、「PDF表示」と「保存」の間、同幅、ラベル「面談サポート」
- 面談レコード必須前提（未作成時は機能しなくてよい）
- オンライン面談: スピーカー出力で本アプリを使う（電話面談と同条件）。環境的に難しい場合のみNotta併用に切り替え
- 自動保存: 面談中も1分ごとに定期保存＋面談終了時に最終保存
- 解説カード: 全件保存（振り返り価値優先）
- 面談サポートタブ（2026-08-27追加）: 面談履歴右カラムに設置。新規作成＋求職者に紐づく全セッションのNotta風一覧＋削除＋閲覧をここで完結。ヘッダーボタンは併存
- 解説方式（2026-08-27 v5）: 自動検知3種カード（用語=積み上げ／業務内容=職務ごと更新型・強み付記／転職理由=1枚更新型）＋即時ボタン2種の併用。希望条件等は検知対象外。話題1行表示は廃止
