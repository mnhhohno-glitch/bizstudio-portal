# LP掲載職種分類のための「経験職種」調査

- 調査日: 2026-09-14
- 対象: 本番DB（Railway / production）**読み取りのみ**。INSERT / UPDATE / DELETE は一切実行していない。
- 期間: 2026-06-01（JST）以降
- アーカイブ済み求職者（`candidates.support_status = 'ARCHIVED'`）は除外
- 重複排除: 求職者（`candidate_number`）単位でユニーク。面談回数では数えていない

## Phase 0: スキーマ確認結果

| 確認項目 | 結果 |

| `WorkHistory` の実カラム | `interview_record_id` / `order` / `company_name`（会社名）/ `business_content`（**業種**）/ `job_type_flag`（**職種：大分類 / 中分類 / 小分類**）/ `job_type_memo`（**業務内容メモ**）/ `tenure_year` / `tenure_month` / `hire_date`(text) / `leave_date`(text) / 退職理由3列 |

| アーカイブ判定 | `candidates` に `archived_at` 列は**存在しない**。判定は `support_status = 'ARCHIVED'` のみ（本番の該当は1件） |
| 日時カラムの型 | `interview_records.interview_date` / `candidates.created_at` ともに `timestamp without time zone`（`information_schema.columns` で確認） |
| `interview_date` の実体 | 全5,572件が時刻 `00:00`。**日付を UTC 0時で保持**しており、時刻は `start_time`(text) 側にある。よって `+ INTERVAL '9 hours'` を足しても日付は動かず 2026-06-01 の境界は変わらない（指示どおり `+ INTERVAL '9 hours'` を明示して使用） |

### 重複（同一職歴が面談ごとに複製される）の実態

対象求職者の `work_histories` 生行数は **1066 行**。職歴を持つ面談レコードが2件以上ある求職者が183名（最多11件）いた。
面談ごとに前回の職歴が引き継がれ、AI解析が文面を微修正して保存し直すため、**単純な文字列一致では重複除去しきれない**（同じ勤務先でもメモ文が数文字違う）。

そこで本調査は **「求職者ごとに、職歴行数が最も多い面談レコード1件を正とする」**（同数なら面談日が新しい方）という規則で1セットに畳んだ。
結果 **501 行 / 285 名**。参考までに「常に最新面談を採る」規則だと 491 行で、**9 名**で採用レコードが食い違う（最新面談の方が職歴が欠けているケース）。

## Phase 2: 経験の一覧

- 職歴は**古い順**（`work_histories.order` 昇順）に「 / 」で連結。
- 各職歴の書式: `職種（大分類 / 中分類 / 小分類） 〔業種: …〕 業務内容メモ`
- **個人情報の扱い**: 氏名・生年月日・連絡先・住所・学校名・**会社名は出力していない**。会社名（`company_name`）はSQL内で重複判定とメモのスクラブにのみ使用し、業務内容メモ中に現れる自社名・法人格つき固有名詞は `〇〇社` に置換した。業種名（`business_content`）は指示どおり残している。
  - スクラブは3段構え: ①その行の `company_name`、②`work_histories` 全体の `company_name` 585件から作った辞書、③法人格つき表記・企業グループ名・勤務先としての学校名・目視で見つけた著名ブランド名の正規表現。置換後は `〇〇社` / `〇〇グループ` / `〇〇校` と表示される（本表で 112箇所）。職種フラグ（固定語彙）は誤マスクを避けるため辞書・正規表現の対象外。

WITH scope AS (

    AND ca.support_status <> 'ARCHIVED'

-- A: 面談日が 2026-06-01 (JST) 以降の求職者数

-- C: A のうち職歴あり / なし
WITH scope AS (...上記...)
SELECT count(*) FILTER (WHERE has_wh)::int      AS with_wh,
       count(*) FILTER (WHERE NOT has_wh)::int  AS without_wh
FROM (
  SELECT s.candidate_id,
         EXISTS (
           SELECT 1 FROM interview_records ir2
           JOIN work_histories w2 ON w2.interview_record_id = ir2.id

  FROM scope s

### Phase 2: 経験の一覧

```sql
WITH scope AS (...上記...),
ir_wh AS (
  SELECT ir.id AS ir_id, ir.candidate_id, ir.interview_date, ir.created_at,
         count(wh.id)::int AS wh_count
  FROM interview_records ir
  JOIN work_histories wh ON wh.interview_record_id = ir.id
  WHERE ir.candidate_id IN (SELECT candidate_id FROM scope)
  GROUP BY ir.id, ir.candidate_id, ir.interview_date, ir.created_at
),
picked AS (
  -- 求職者ごとに「職歴行数が最も多い面談」を1件だけ採用（同数なら面談日が新しい方）
  SELECT ir_id, candidate_id,
         row_number() OVER (
           PARTITION BY candidate_id
           ORDER BY wh_count DESC, interview_date DESC, created_at DESC
         ) AS rn
  FROM ir_wh
)
SELECT ca.candidate_number,
       wh."order"          AS wh_order,
       wh.company_name,      -- 重複判定・メモのスクラブ用。md 出力には含めない
       wh.business_content,  -- 業種
       wh.job_type_flag,     -- 職種（3階層）
       wh.job_type_memo,     -- 業務内容
       wh.tenure_year, wh.tenure_month
FROM picked p
JOIN candidates ca ON ca.id = p.candidate_id
JOIN work_histories wh ON wh.interview_record_id = p.ir_id
WHERE p.rn = 1
ORDER BY ca.candidate_number, wh."order", wh.id;
```

  FROM interview_records ir JOIN work_histories wh ON wh.interview_record_id = ir.id

-- 「最多職歴の面談」と「最新の面談」で採用レコードが食い違う人数
WITH scope AS (...上記...), ir_wh AS (...上記...),
a AS (SELECT candidate_id, ir_id, row_number() OVER (PARTITION BY candidate_id ORDER BY wh_count DESC, interview_date DESC, created_at DESC) rn FROM ir_wh),
b AS (SELECT candidate_id, ir_id, row_number() OVER (PARTITION BY candidate_id ORDER BY interview_date DESC, created_at DESC) rn FROM ir_wh)
SELECT count(*)::int AS differ FROM a JOIN b USING (candidate_id)
WHERE a.rn = 1 AND b.rn = 1 AND a.ir_id <> b.ir_id;
