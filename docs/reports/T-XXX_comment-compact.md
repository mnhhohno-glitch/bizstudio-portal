## 1. コメントの使われ方（調査）

| 場所 | 使い方 | 今回の形式で守るもの |
|--|--|--|
| 評価の取り出し `extractRatingsAndComments`（`src/lib/analyze-bookmarks.ts`） | 「【会社名】…」見出しで求人ごとに切り出し、`■ 総合:` からランク。項目行「【項目名】記号」は `NOT_CA_ITEM` で区切りと誤認しない | 見出し・3軸行・項目行の形 |
| 保存の条件 `hasValidThreeAxisMarkers` | `■ 本人希望:` `通過率:` `総合:` が揃った行だけ保存（fail-closed） | 3軸行 |
| CA 画面（`HistoryTab.tsx`・自動配信承認 `AutoRecommendApprovalClient.tsx`） | `splitAnalysisForTabs` / `parseCaAnalysisBlocks` で本人向けと CA 向けに分け、項目行を 〇▲× のバッジ表示 | 「◆ おすすめポイント（本人向け）」「◆ 選考分析（CA向け）」見出し・項目行 |
| 完了カード（analyze-batch route） | 総合まとめ（バッチ指示側）と件数のみ。コメント本文は使わない | 変更なし（バッチ指示は触っていない） |
| 総合まとめ用の圧縮 `compressBatchResultForSummary` | 会社名見出し＋3軸だけ残す | 見出し・3軸行 |
| **求職者向けサイト** | `candidate-site-favorite-dto.ts` → `extractRecommendationForDisplay`（`comment-split.ts`）。**「◆ おすすめポイント（本人向け）」と「◆ 選考分析（CA向け）」が正順で揃う時だけ**、その間の本文を Markdown 除去して表示（CA 向けは漏れない）。旧経路の `extractCandidateFacingComment`（kyuujinPDF 送信・sync-ca-comments）も同じ見出しで切り出す | 2つの見出しと順序。本人向け本文は短くなるだけ |

指示文のうちコメントの形式を決めているのは、固定部（`buildAnalyzeFixedSystem` = SKILL + `EVAL_RULES`）の **「## 出力フォーマット」節**。手動評価（analyze-batch）と自動配信（`src/lib/recommend/analyze-batch-run.ts`）で共通。

### 9月の試み（6c6287e・`docs/reports/T-189_output_compact_staging_verification.md`）
- 選考分析を「▲/×で始まる指摘だけ1行40字」に変え、〇項目を消した。本人向けは総評120字
- 10件中3件で書式由来のランク変化（▲行の統合・脱落で ▲ の数が減り B+→A など）。旧▲×項目の減少 5/10 で撤退

### 今回の方針（9月との違い）
- 項目の形（「【項目名】記号」＋コメント1行）は T-180 のまま。**〇項目も残す**（全項目を確定してから数える手順を崩さない）
- 短くするのは各項目のコメント文（短い一文・目安40字）と本人向け総評（2〜3文・目安3行）だけ
- **▲・× は判定で付けたものを1つ残らず1項目1行で書く・まとめない・省かない・言い換えて減らさない**を最優先ルールとして明記
- 前置き・求人票の書き写し・締めの挨拶を禁止
